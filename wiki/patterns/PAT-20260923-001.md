## 症状 / 场景

在 wiki/ 由多个并发会话共同写入的仓库里：(1) git add wiki/ 会把其他会话正在写入的记录一并卷入提交，致提交信息与实际内容不符；(2) 对已推送提交执行 git commit --amend 后 push 被拒（fast-forward 失败），本地与远端分叉。

## 根因

wiki/ 无写入锁，多会话共享同一工作树；且 git 提交一经推送即为他方已见的事实，改写会破坏 fast-forward 前提。

## 可执行对策（workaround）

提交时用 git add <具体路径> 而非整目录；若已卷入他会话记录，如实写入提交信息而非 amend 掩盖。一旦推送，禁止 amend/rebase，改用新提交修正信息；误 amend 后先比对 tree（git rev-parse X^{tree}），tree 相同则 git reset --hard <远端>，不同则 revert。

## 证据

R68: amend 已推送提交导致分叉；git add wiki/ 卷入 ISSUE-0129..0159（31 个 issue）；git rev-parse 0a1b72b^{tree} == 4b40abf^{tree} == d07051217a5d，故用 git reset --hard 0a1b72b 安全收敛，HEAD == private/main
